Sekondi

The customs shed at Sekondi harbour has two halls. The General Goods hall runs on the ordinary rulebook Kofi knows by heart. Cargo for the fishing co-operative is checked in a separate hall, under the co-op's own rulebook — different forms, different allowed-list, different idea of what counts as contraband. A drum of a certain chemical can be perfectly legal in the fishing hall (it preserves nets) and flatly banned in General Goods.

Here is the trap. A crate can be checked in the fishing hall, passed, resealed — and then, further down the dock, re-sorted into the General Goods stream because of how it was stacked. Now it is being judged by the other rulebook, and the officer who passed it never applied that one. That re-sort is a namespace boundary, and standing in it is how mutation XSS works.

01

What a namespace is

An HTML document can contain three different vocabularies of elements, each with its own identifier called a namespace URI:

VocabularyNamespace URIEntered by
HTML (the default)http://www.w3.org/1999/xhtml— you start here
SVGhttp://www.w3.org/2000/svgan <svg> start tag
MathMLhttp://www.w3.org/1998/Math/MathMLa <math> start tag

Every element node carries its namespace for life. In JavaScript you read it as el.namespaceURI and create one with document.createElementNS(ns, name). The parser assigns it automatically based on where the tag appeared.

Why it matters for security

A sanitizer's allowed-list is usually written for HTML element names: "allow <a>, <b>, <title>." But <a> in the SVG namespace is a different element from <a> in HTML, and SVG <title> behaves nothing like HTML <title>. A check that looks at the tag name and not the tag namespace is checking the wrong thing.

02

"Foreign content" mode changes the rules

The moment the tree builder processes <svg> or <math> it enters a mode the standard calls foreign content. Inside it, several HTML behaviours you rely on switch off:

  • No RAWTEXT / RCDATA. In HTML, <style>, <script>, <title>, <textarea> make the tokenizer treat everything up to the close tag as plain text. Inside <svg>/<math>, they do not — the content is parsed as ordinary elements.
  • Self-closing works. <circle/> really closes.
  • CDATA sections are allowed. <![CDATA[ … ]]> becomes text. In HTML it becomes a bogus comment.
  • Some names are case-corrected: viewbox→viewBox, foreignobject→foreignObject.
03

Getting back out: integration points and breakout tags

Integration points — a deliberate door back to HTML

Certain foreign elements are declared HTML integration points or text integration points: their content parses under HTML rules even though the element itself is foreign.

  • SVG: <foreignObject>, <desc>, <title>
  • MathML text integration points: <mi>, <mo>, <mn>, <ms>, <mtext>
  • MathML: <annotation-xml> with encoding="text/html" or "application/xhtml+xml"

Breakout tags — an accidental ejection

If the parser is in foreign content and sees the start tag of a common HTML element — <b>, <i>, <p>, <br>, <img>, <table>, <div>, headings, list items… PARSE ERROR it pops every foreign element off the stack until it is back in HTML, then processes the tag normally. So <svg><p> does not give an SVG paragraph; it ends the <svg> and starts an HTML <p> as a sibling.

new DOMParser().parseFromString(html, 'text/html')

html = '<a></a><svg><a></a></svg>'
  first <a>  .namespaceURI  ->  http://www.w3.org/1999/xhtml   (HTML)
  svg > a     .namespaceURI  ->  http://www.w3.org/2000/svg     (SVG)

html = '<svg><style>abc<def>ghi</def></style></svg>'
  svg style .innerHTML  ->  "abc<def>ghi</def>"    <def> is an ELEMENT, not text
                                              (in HTML, <style> content is always text)

html = '<svg><desc><img src=x onerror=1></desc></svg>'
  desc .firstChild  ->  <IMG> element     <desc> is an HTML integration point

html = '<svg><p>hi</p></svg>'
  p .namespaceURI   ->  http://www.w3.org/1999/xhtml
  p .parentElement  ->  BODY               <p> broke out of <svg> entirely

04

Why this is a mutation-XSS engine, in one line

A sanitizer parses <svg><style>…</style></svg>, sees the <style>'s children as harmless SVG elements, decides they are fine, and serializes. When the browser re-parses that string without the <svg> wrapper — because the sanitizer removed it, or the node was moved — the same <style> is now an HTML <style>, its children collapse into one text node, and the < characters that were safely inside a child element are raw text that the next parse reads as tags. The officer in the fishing hall passed it. The General Goods rulebook was never applied.

Reality check — many classic namespace payloads are now patched

Browsers changed serialization over the years to close these. The most-quoted payload — <svg><style><a title="</style><img src=x onerror=alert(1)>"> — does not round-trip in Chrome 148: the attribute's </> serialize as &lt;/&gt; and stay inert. Module 5 shows which variants are still live, which are version-specific, and which are history — each re-tested against the browser you have.
