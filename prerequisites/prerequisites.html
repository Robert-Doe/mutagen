Ten IdeasEvery Module Assumes

Mutation XSS lives at the seam between four machines: the tokenizer, the tree builder, the serializer, and the sanitizer. You don't need to build all four from memory — you need a correct model of each. This page is the map.

☞

Sekondi

Picture the customs shed at Sekondi harbour where Kofi works Saturdays. A crate arrives. Someone has to read the manifest (tokenizer: turn a stream of characters into a list of labelled items), lay the goods out on the table in the right groupings (tree builder: turn that flat list into a nested structure), write a fresh manifest when the crate is repacked (serializer), and check every item against the allowed list (sanitizer). Four jobs, four rulebooks. Mutation XSS is a disagreement between those rulebooks that a smuggler can stand in.

1 — Namespaces: HTML, SVG, MathML

The same tag name means different things depending on which namespace the parser is in. <style> inside <svg> does not start CSS rawtext the way it does in HTML. The parser switches namespace at <svg>/<math> and back at "integration points". Modules 1 and 5 are built on this. Read before Module 1.

2 — The Scripting Flag

A boolean input to the parser that changes how <noscript> is parsed: scripting on → raw text; scripting off → normal markup. A browser has it on; a server-side sanitizer has it off. Same string, two trees. Module 4 is this bug. Read before Module 4.

3 — The DOM node shape

A parsed document is a tree of nodes: a Document / DocumentFragment root; Element nodes (tag name, attribute map, ordered children); Text nodes; Comment nodes. An element's parent and its ordered children are the only structure there is. mXSS is almost always "a node ended up with a different parent than the source markup implied."

Deep Foster Parenting → DOM node shape

4 — Parsing vs. serialization: two directions, two rulebooks

Parsing is string → tree. Serialization is tree → string — what you get reading element.innerHTML. Separate algorithms in the standard (§13.2 and §13.3), never designed as exact inverses. The gap between them is where this whole course lives. Module 2 builds the serializer and shows the gap.

5 — Tokens and tokenizer states

Before the tree there is a flat list of tokens: start-tag, end-tag, character, comment, DOCTYPE. The tokenizer is a state machine: in "data" state a < begins a tag; in "RAWTEXT" state (inside <style>, <script>, <xmp>) a < is just a character and only the matching close tag ends the block. "Which state am I in?" has no answer without context — the seam Module 3 exploits.

Deep Tokenization → finite state machines Tokenization → Module 5

6 — Content models: normal, void, rawtext, RCDATA, foreign

Every element has a content model deciding how its children parse. Normal: markup. Void (<img>): no children. RAWTEXT (<style>, <script>): literal text, no entities, no tags. RCDATA (<title>, <textarea>): literal text but entities decode. Foreign (inside <svg>/<math>): different again. Move a subtree from a rawtext parent to a normal parent and its "text" is suddenly markup. Module 3.

7 — Character references (entities)

&lt;, &#60;, &#x3c; all decode to <. When they decode is contextual: in attribute values and RCDATA text, yes; in RAWTEXT and comments, no. A serializer that writes &lt; into a place the next parse will decode has handed the attacker a <. Module 6.

Deep Tokenization → Module 4

8 — The stack of open elements & insertion modes

The tree builder keeps a stack of elements it is currently inside and an insertion mode ("in body", "in table", "in template"…). "In table" mode foster-parents non-table content — relocates it to just before the table. A legal, spec-mandated mutation. The Foster Parenting course is entirely about it.

Deep Foster Parenting → stack of open elements → insertion modes

9 — Idempotency and fixed points

f is idempotent if f(f(x)) = f(x) for every x. HTML parse‚serialize is not. A sanitizer whose parse‚serialize step is not idempotent must be run in a loop until its output stops changing, or the browser's final parse can differ from the tree it approved. Module 2, and the fix in Module 8.

Deep Foster Parenting → T2-04

10 — What "XSS" and "a payload" mean

XSS: attacker-controlled JavaScript runs in the victim's page with the victim's privileges. A payload is the minimal markup that shows it — here almost always <img src=x onerror=alert(1)>: broken image → onerror fires → alert(1) runs. Alert box appears → script ran. That is the entire test.
