You build a small HTML engine, a serializer, and a sanitizer — then break your own sanitizer one mutation class at a time, and fix it. Every claim on every page was produced by running real code, then checked against a real browser.

The one fact this whole course exists to prove

HTML parsing is not idempotent.

parse( serialize( parse(x) ) )  ≠  parse(x)

A sanitizer computes clean = serialize(sanitize(parse(dirty))). The browser then runs parse(clean) at innerHTML. If that last parse builds a tree the sanitizer never saw — and it runs script — that is mutation XSS.

Meet Kofi

Every module is anchored to one person: Kofi, sixteen, who lives a few streets up from the fishing harbour in Sekondi, on Ghana's western coast. On Saturdays Kofi helps at the customs shed at the port — opening crates, checking the contents against a list of what's allowed in, nailing them shut again, sending them on.

That is the whole of mutation XSS in one picture. A sanitizer is the customs officer with the allowed-list. Parsing is opening a crate to see what is really inside. Serialization is nailing it shut again. Mutation XSS is the next officer down the dock opening that resealed crate and finding something the first officer would never have passed — not because anyone tampered with it in transit, but because the rules for packing a crate and the rules for unpacking one do not perfectly mirror each other. Hold onto Kofi. He is on every page.

Running the code

Everything runs with Node.js (v20+) and a browser. No build step, no framework, no dependencies. Each module's 06 — Run It section gives the exact PowerShell commands and the exact expected output. The from-scratch engine every module imports lives at engine/mxss-lab/lab.mjs.

node --version   # expect v20 or higher
cd track1-engine\01-foreign-content-fragment ; node test\demo.mjs
