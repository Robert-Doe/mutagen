Attribute Serializationthe four-character fix

Character references and quotes inside an attribute value used to break out of that attribute on the next parse. This module shows the exact payloads, the pre-2020 serializer that produced them, and the four characters the modern serializer now escapes to close the whole class.

What this module proves

The pre-2020 attribute serializer escaped only & and ". The modern one also escapes < and >. That two-character addition — verified in Chrome 148 — is why an entire generation of "entity in an attribute" mXSS payloads are museum pieces.

01

The Big Analogy

Kofi labels a crate's contents in a single boxed field on the manifest: [ pineapples, ripe ]. The rule for reading that field: everything between the brackets is one description, commas and all.

A smuggler writes [ pineapples ] [ rifles ] in the field. If Kofi copies it onto the next manifest with the brackets he found, the next officer reads two fields — pineapples, and rifles. The save is a rule Kofi's clerk added in 2020: when you copy a field, turn any stray bracket in it into the written word "bracket". Now the next officer reads one weird description — "pineapples bracket bracket rifles bracket" — and files it as produce. The stray brackets (< and >) became text.

02

What Happens, Step by Step

  1. Attacker submits <x title="&lt;/title&gt;&lt;img src=x onerror=alert(1)&gt;">.
  2. Parser: attribute values do decode entities, so the tree has x with title = "</title><img src=x onerror=alert(1)>" — a string. No element, no handler. The sanitizer approves it.
  3. Pre-2020 serialize: & and " escaped; </> left raw → title="</title><img src=x onerror=alert(1)>".
  4. That string, re-emitted unquoted by an old IE serializer, or piped into an XML/template consumer, or extracted from a <template> (Module 7): the <img> is now a tag. XSS
  5. 2026 serialize: title="&lt;/title&gt;&lt;img src=x onerror=alert(1)&gt;". RCDATA/RAWTEXT don't decode; a plain HTML re-parse keeps it a string. Dead.

The Code, Explained

// modern (engine/mxss-lab/lab.mjs)
escapeAttr(s) = s.replace(/&/,'&amp;').replace(/\u00a0/,'&nbsp;')
                 .replace(/"/,'&quot;').replace(/</,'&lt;').replace(/>/,'&gt;');

// legacy — the two green calls above simply weren't there
escapeAttrLegacy(s) = s.replace(/&/,'&amp;').replace(/\u00a0/,'&nbsp;').replace(/"/,'&quot;');

bothSerializers(payload) parses once, serialises both ways, and re-parses each with scripting on. Rationale: DECISIONS.md.

07

Brain Exercise

If quoted attribute values are safe from </> break-out anyway (the quote ends the value), why did browsers bother adding the escape?

Because the serialized string doesn't only get re-parsed as HTML. It gets: assigned to another element's innerHTML (fine), but also document.write()n, concatenated into a larger template, fed to an XML parser, stored and later rendered server-side, or — Module 7 — extracted from a <template>'s inert fragment and inserted live. In several of those, the value is re-tokenized in a state where the quote context is lost. Escaping </> at serialization time makes the string safe regardless of who consumes it next, which is the only property worth having.

08

There Are No Dumb Questions

Q: What was the IE backtick vector?
A: Internet Explorer treated ` as a quote character in unquoted attribute values. <img src=`xx`onerror=alert(1)> parsed as src="xx" + onerror="alert(1)" in IE, and sanitizers that only knew about " and ' missed it. No current browser does this; it's in src/attributes.mjs as IE_BACKTICK_HISTORY, documented for the timeline, not run.
Q: Do attribute values really decode entities during parsing?
A: Yes — the tokenizer's "attribute value" state consumes character references. That's why href="?a=1&amp;b=2" works. It's also why &lt; in a submitted attribute becomes a real < character in the parsed tree — the thing this module is about.
Q: So is Module 6 just history?
A: The plain HTML re-parse version is. The mechanism — "a value that's data in the tree becomes markup when re-emitted into the wrong context" — is exactly Module 7's <template> extraction and Module 9's document.write sink. This module is where you learn to see it.
