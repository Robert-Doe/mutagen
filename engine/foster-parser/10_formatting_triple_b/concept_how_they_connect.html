C

Commonly confused pairs

The wrong statementThe correction
"Foster parenting and the adoption agency algorithm are two names for the same thing." No — the adoption agency is a much larger algorithm for fixing misnested formatting-element end tags; foster parenting is a small two-condition gate. They only ever meet at one point: the adoption agency's final relocation step can, incidentally, trigger fostering.
"Reconstruction repairs a tree that got broken." No — reconstruction runs routinely on nearly every relevant insertion and does nothing most of the time (step 2's early exit). It isn't a repair mode; it's a constant, cheap check that occasionally finds real work to do.
"The parser reparents the <b> element when the table clears the stack." No — clearing the stack only pops the element off the STACK. Nothing "reparents" it anywhere; it stays exactly where it already was in the tree, orphaned only from the stack's bookkeeping. The NEW <b> that shows up later is a freshly created element, not the old one moved.
"React/Vue 'reparenting' a component and the HTML parser's foster parenting are related concepts." No — framework "reparenting" (moving a live DOM node with appendChild/moveBefore to preserve component state) happens at runtime, on an already-parsed document, using ordinary DOM methods. Tree construction is not involved and the term's use in both contexts is a naming coincidence, not a shared mechanism.

Scenario-matching quiz

For each scenario, name which ONE of the four terms is responsible before revealing the answer.

A page calls document.getElementById('a').appendChild(document.getElementById('b')) in a <script> tag, moving an already-rendered element.

DOM "reparenting" — ordinary DOM mutation, long after parsing finished. None of the other three terms are running at this point at all.

<table><p>x</p></table> — the <p> ends up as a sibling before the table.

Foster parenting — a plain, unhandled start tag hits in table's anything-else fallback, current node is table, both gate conditions hold.

<a href=1>x<a href=2>y</a> — the second <a> implicitly closes the first, in a way that isn't a simple stack pop.

The adoption agency algorithm — repeated/misnested <a> tags are one of the algorithm's classic trigger cases (alongside <nobr>).

<table><b><tr><td>aaa</td></tr>bbb</table>ccc — the second <b> appears with no corresponding start tag anywhere near it in the source.

Reconstruction — the active-formatting list still has the (stack-orphaned) first <b>'s entry; reconstruction creates a fresh element for it. (It then ALSO gets fostered, since current node is tr — two of the four terms cooperating, which is exactly this module's point.)
