DOM"Reparenting"

A completely different thing that developers call "reparenting," using ordinary DOM methods, after a page has already parsed. Zero relationship to anything else on this page — included specifically because the name-collision causes real confusion.

Someone, well after the building is fully constructed and occupied, physically picks up a piece of furniture and carries it to a different room. Nothing about the estate's gate rules, corridor rules, or guest lists is involved — the building is done being built. This is a mover, not a parser.

What developers mean by it: calling someElement.appendChild(otherElement) (or moveBefore, replaceChildren, etc.) to move an already-existing DOM node to a new parent, typically to preserve component state (e.g. keeping an <iframe> or a video element from reloading when a UI framework re-renders it into a different part of the tree).

Why it has nothing to do with this course: Prerequisite P5 and every module since is about tree construction — the algorithm that runs while the tokenizer is still feeding the parser tokens from a source string. DOM mutation methods like appendChild run after parsing is done, or completely independent of parsing altogether (e.g. building a tree from scratch with document.createElement). The attached reference course's own Module 01 says this directly, as lever 4 of "what you actually control": "DOM mutation is not tree construction. table.appendChild(document.createElement('p')) puts a <p> inside a <table> and no rule in §13.2 has anything to say about it."

The confused pair

Search results and casual usage often use "reparenting" for BOTH this DOM-mutation sense AND, loosely, for what foster parenting does ("the parser reparents the node"). The spec itself never uses "reparent" for foster parenting — it says "foster parenting" specifically, precisely to avoid this exact collision. If a source uses "reparenting" without qualification, check which sense it means before assuming it's about tree construction at all.

How this connects

It doesn't — that's the point of including it. Foster parenting, the adoption agency, and reconstruction are all tree-construction-time mechanisms, active only while the tokenizer is still producing tokens from source text. This is a runtime DOM-API operation with no connection to parsing at all. Sharing a page with the other three exists solely so a reader who arrives here confused about which "reparenting" a piece of documentation means leaves un-confused.
