Track 2 studied one round trip. This module zooms out: a browser has at least seven ways to turn a string into DOM, they disagree, and mutation XSS is just the cell where a sanitizer used one and the app used another.

What this module proves

<noscript><img src=x onerror=alert(1)></noscript> is live through DOMParser and template.innerHTML, and inert through element.innerHTML. The string didn't change. The sink did.

The Big Analogy

One shipping manifest. Seven customs offices along the route, each with its own way of reading it: the port office reads it as bonded cargo, the airport as air freight, the rail depot ignores the "fragile" column entirely, the bonded warehouse treats every unlisted item as duty-free, the border post applies quarantine rules the others don't. Same sheet of paper. Whether a crate is "contraband" depends on which office opened it. Kofi's shed and the warehouse next door reach different verdicts on the identical manifest — and the smuggler routes through the pair that disagree.

export function sinkDifferential(html) {
  return {
    'innerHTML (div, on)':  parseFragment(html, 'div',      {scripting:true}),
    'innerHTML (body, on)': parseFragment(html, 'body',     {scripting:true}),
    'DOMParser (off)':      parseDocument(html,             {scripting:false}),
    'template.innerHTML':   parseFragment(html, 'template', {scripting:false}),
  };  // sinks 4 & 7 (Range, document.write) are browser-only — see the table

07

Brain Exercise

Your sanitizer uses DOMParser (sink 3). Your app renders with a framework that uses range.createContextualFragment (sink 4) into a <td>. Name a string that is safe through sink 3 and dangerous through sink 4.

Anything whose parse depends on being inside a table cell and on the scripting flag. Sink 3 parses at document level, scripting off; sink 4 parses with context <td> (so "in cell" insertion mode) and scripting on. A payload using <noscript> gets the flag divergence; one using foster-parenting-shaped markup (<table> tricks — see the Foster Parenting course) gets the context divergence; combine them. The defence is the same as Module 8: don't rely on your sanitizer's parse matching the sink's — forbid the constructs that diverge, and loop to a fixed point so the string is stable regardless of who parses it.

08

There Are No Dumb Questions

Q: Is outerHTML really different from innerHTML?
A: The parse context differs by one level (the parent, not the element), which changes the insertion mode. For a <td>: td.innerHTML parses "in cell"; td.outerHTML parses "in row". Different rules for the same string.
Q: Why does XML serialization matter for XSS?
A: Code that does new XMLSerializer().serializeToString(el) then feeds the result to innerHTML (a real pattern in XSLT and some editors) gets <script/>-style self-closing tags that HTML re-parses as unclosed, swallowing following content into the element — a structural mutation.
Q: Does the native Sanitizer API dodge all this?
A: Largely yes — it parses once and hands you a node, no serialize step, so there's no second sink to disagree. That's Module 11.
