Foreign Content& the Fragment Parser

Before any attack, the machine. This module proves the tree builder switches parsing rules at <svg> and <math>, switches back at integration points, and gets kicked out by breakout tags — and that element.innerHTML = "…" starts the parser in whatever mode the context element dictates.

What this module proves

The string <style><img src=x onerror=1> is a single inert text node when its parent is an HTML <style>, and a live <img> element when its parent is an SVG <style>. Same characters. The parent's namespace decides.

01

The Big Analogy

Kofi's customs shed has the General Goods hall and the fishing co-operative's hall. Walk a crate through the door marked <svg> and you are now in the co-op's hall, under the co-op's rulebook. In there, a sealed drum labelled "engine oil" (<style>) is opened and its contents sorted — the co-op doesn't have the General-Goods rule that says "drums labelled oil are set aside unopened".

Three things can send you back to the General Goods rulebook. One is a marked door in the co-op wall — <foreignObject>, <desc>, <mtext> — an integration point, put there on purpose. The second is turning up in the co-op hall holding something that obviously belongs in General Goods — a pallet of <p>, a crate of <table>. Security doesn't sort it; they walk you and it all the way back out. That's a breakout tag. The third is the one that matters most for the attacks: someone hands the officer a crate and says "check this as if it were already sitting inside drum #47". That instruction — the context element — is element.innerHTML = "…".

02

What Happens, Step by Step

  1. The tree builder starts in the HTML namespace. Every element it inserts is HTML.
  2. It processes a <svg> (or <math>) start tag: it creates that element in the SVG (MathML) namespace and pushes SVG (MathML) onto its namespace context.
  3. While the namespace context is foreign: <style>, <title>, <textarea>, <script> do not switch the tokenizer to a text mode. Their children are parsed as elements. Self-closing works. <![CDATA[…]]> is text.
  4. If it hits an integration point element (<foreignObject>, <desc>, <title> in SVG; <mi><mo><mn><ms><mtext> in MathML), it parses that element's content under HTML rules again.
  5. If it hits a breakout tag (<b> <i> <p> <br> <img> <table> <div>…) while foreign, it PARSE ERROR pops every foreign element off the stack, back to HTML, and reprocesses the tag.
  6. One exception inside a MathML text integration point: <mglyph> and <malignmark> stay in MathML. (This is the hinge of Module 5.)
  7. For a fragment parse (innerHTML), the context element seeds step 1: a <textarea> context starts in RCDATA, a <svg> context starts foreign, a <div> context starts normal.
03

A Map of This Module's State

<style><img src=x onerror=1></style> (HTML)

#fragment
└─ style
   └─ #text "<img src=x onerror=1>"   inert

<svg><style><img src=x onerror=1></style></svg>

#fragment
└─ svg {svg}
   └─ style {svg}
      └─ img {svg} onerror="1"   a real element

The <img> is a breakout tag, so a bare <svg><style><img> actually ejects to HTML — but <svg><style><image> or any non-breakout child stays SVG. Module 5 uses exactly this gap.

04

The Code, Explained

The engine is engine/mxss-lab/lab.mjs. The foreign-content decision, in insertStart:

// while the namespace context is foreign …
if (curNs() !== HTML) {
  if (BREAKOUT.has(name)) {
    // … a common HTML tag pops us all the way back to HTML
    while (stack.length > 1 && curNs() !== HTML) { stack.pop(); nsStack.pop(); }
  } else {
    // … otherwise insert a FOREIGN element in the current namespace
    const el = new El(name, curNs());
    const isIntegration =
      (ns === SVG   && SVG_HTML_INTEGRATION.has(name)) ||
      (ns === MATHML && MATHML_TEXT_INTEGRATION.has(name));
    nsStack.push(isIntegration ? HTML : ns);   // integration point → HTML rules for content
  }
}

And the fragment context, in build():

if (RAWTEXT.has(context)) { seedMode = 'rawtext'; }      // <style> context
else if (RCDATA.has(context)) { seedMode = 'rcdata'; }   // <textarea> context
else if (context === 'svg') nsStack.push(SVG);           // <svg> context

Full rationale, and why we wrote a fresh 450-line engine instead of bending the Foster Parenting course's dispatch14 (which throws NotImplementedYet on <noscript>, <template> in head, and foreign content): DECISIONS.md.

07

Brain Exercise

<svg><desc><svg><style><img src=x onerror=1></style> — where does that <img> end up, and what namespace is it?

An HTML <img>, and a sibling of the inner <svg> — the <style> ends up empty. Work the stack: outer <svg> → SVG. <desc> → HTML integration point, content parses as HTML. The inner <svg> tag, processed under HTML rules, re-enters foreign content, so the inner <style> is SVG (not rawtext). Then <img> is a breakout tag: it pops the inner <style> and the inner <svg> off the stack, back to the <desc>'s HTML context, and inserts the <img> there in the HTML namespace. Verified against Chrome 148: img.parentElement is <desc>, style.childNodes.length is 0. The lesson: "text or element, and where" is never answerable from the tag alone — you walk the whole stack of namespaces above it. Run our engine to see the same tree: node -e "import('./src/foreign.mjs').then(m=>console.log(m.treeString(m.parseFragment('<svg><desc><svg><style><img src=x onerror=1></style>','body')).join(String.fromCharCode(10))))".

08

There Are No Dumb Questions

Q: Is switching namespace a bug?
A: No — it is the whole point of being able to put SVG and MathML inside HTML without a separate document. It is specified, intentional, and every browser does it identically. The "bug", when there is one, is in code that reasons about markup without accounting for it.
Q: Why does <svg><style> not go rawtext, when the whole reason <style> exists is to hold CSS?
A: Inside SVG, styling is done with SVG's own <style> element, which is an ordinary element node in the SVG DOM — its text content is CSS, but the parser doesn't give it special tokenizer treatment. Only the HTML parser has the RAWTEXT shortcut, and only for the HTML <style>.
Q: The prereq said the classic <svg><style> payload is patched. So why build this module?
A: Because the mechanism — "a node's meaning depends on the namespace of its ancestors, and serialize+reparse can change that" — is not patched and cannot be. Individual payloads get closed by serialization tweaks; the class stays open. Module 5 shows live 2026 variants.
Q: Does DOMParser really parse foreign content the same as innerHTML?
A: For namespaces and integration points, yes. They differ on the scripting flag (Module 4) and on document-vs-fragment wrapper elements, not on foreign content.
