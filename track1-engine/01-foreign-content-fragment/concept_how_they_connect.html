The SVG Stuffsix terms people merge into one

"The SVG stuff" is not one idea. It is six, and Module 5's bypasses turn on telling them apart.

01

Side by side

namespacea label on every element node (el.namespaceURI): one of HTML, SVG, MathML. Fixed at creation.on the node, forever

03

Commonly confused pairs

The wrong statementThe correction
"<desc> is in the HTML namespace because its content is HTML."The <desc> element is in the SVG namespace (desc.namespaceURI = the SVG URI). Only its content parses with HTML rules. Namespace ≠ parsing mode.
"Foreign content means the elements aren't real / aren't in the DOM."They are fully real DOM nodes. "Foreign" is about which vocabulary they belong to, not whether they exist.
"A breakout tag and an integration point both get you back to HTML, so they're the same."An integration point is a door — the foreign elements stay on the stack, you're just parsing their children as HTML. A breakout tag is an ejection — the foreign elements are popped off the stack and the tag becomes their sibling.
"<mglyph> inside <mtext> parses as HTML, like everything else in <mtext>."<mglyph> and <malignmark> are the one exception — they stay MathML. That is precisely why they appear in DOMPurify bypasses.
"The fragment parsing context is just the element I assign innerHTML to; it doesn't change anything."It seeds the insertion mode. A <textarea> context makes <img src=x onerror=1> inert text; a <div> context makes it a live element. Same string.
04

Scenario-matching quiz

<math><mtext><b>x</b></mtext></math> — what namespace is <b>?

HTML. <mtext> is a MathML text integration point; its content parses as HTML, so <b> is an HTML element (verified: b.namespaceURI = the xhtml URI).

<math><mtext><mglyph><style><img src=x onerror=1></style> — is that <img> an element?

Yes. <mglyph> stays MathML, so <style> is a MathML element (not rawtext), so <img> is a real child element. This is the shape of a still-live 2026 bypass — Module 5.

<svg><div>hi</div></svg> — is <div> inside <svg>?

No. <div> is a breakout tag. The <svg> is popped off the stack; <div> becomes its sibling, in the HTML namespace.

You do document.createElementNS(SVG_NS, 'a') then document.body.appendChild(it). Was any parsing involved?

No. That is DOM mutation, not tree construction. No insertion mode, no foreign-content rules — you directly created an SVG-namespaced <a> and attached it. Sanitizers that only reason about parsed markup can miss nodes created this way.
